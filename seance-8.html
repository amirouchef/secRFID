Journalisation et horodatage des accès

Fil rouge : vous ajoutez une trace des tentatives d'accès au système sécurisé construit en séance 7, avant de lancer le projet final en séance 9.

Cours

1. Pourquoi journaliser les accès ?

Un contrôle d'accès sans journal ne permet ni de détecter une anomalie (tentatives répétées, horaires inhabituels) ni d'enquêter après un incident. La journalisation est un principe de sécurité à part entière, indépendant du chiffrement de la carte.

2. L'horodatage sur Arduino

L'Arduino Uno n'a ni horloge réseau ni pile de sauvegarde : millis() ne donne qu'un temps relatif depuis la dernière mise sous tension, pas une heure réelle. Un vrai système utiliserait un module RTC (Real-Time Clock) à pile, non fourni dans ce kit.

3. Limites d'une journalisation locale

Stockée uniquement dans la mémoire volatile de l'Arduino, la journalisation est perdue à chaque coupure d'alimentation et n'est consultable que localement. Un système réel enverrait chaque évènement à un serveur central, horodaté par une source fiable.

Atelier

Objectif : enrichir le contrôle d'accès de la séance 7 avec un historique horodaté des tentatives.

Étape 1 : repartir du code existant

Repartez du sketch de la séance 7 (UID + secret). Gardez une copie de sauvegarde avant de le modifier.

Étape 2 : définir la structure d'historique

struct Tentative {
  byte uid[4];
  unsigned long horodatage;
  bool autorisee;
};

const byte TAILLE_HISTORIQUE = 10;
Tentative historique[TAILLE_HISTORIQUE];
byte indexHistorique = 0;
byte nbTentatives = 0;

Étape 3 : enregistrer chaque tentative

Juste après avoir déterminé si l'accès est autorisé, ajoutez :

memcpy(historique[indexHistorique].uid, rfid.uid.uidByte, 4);
historique[indexHistorique].horodatage = millis();
historique[indexHistorique].autorisee = autorise;
indexHistorique = (indexHistorique + 1) % TAILLE_HISTORIQUE; // écrase le plus ancien
if (nbTentatives < TAILLE_HISTORIQUE) nbTentatives++;
✓ Résultat attendu : le programme continue de fonctionner normalement, sans effet visible pour l'instant (l'historique se remplit en silence).

Étape 4 : afficher l'historique sur commande

Dans loop(), en plus de la lecture RFID, surveillez l'entrée série :

if (Serial.available() && Serial.read() == 'h') {
  Serial.println(F("--- Historique des tentatives ---"));
  for (byte i = 0; i < nbTentatives; i++) {
    Serial.print(F("UID: "));
    for (byte j = 0; j < 4; j++) {
      if (historique[i].uid[j] < 0x10) Serial.print("0");
      Serial.print(historique[i].uid[j], HEX);
    }
    Serial.print(F(" | t+"));
    Serial.print(historique[i].horodatage / 1000);
    Serial.print(F("s | "));
    Serial.println(historique[i].autorisee ? F("AUTORISE") : F("REFUSE"));
  }
}

Téléversez, faites quelques tentatives (badge légitime, puis clone s'il reste fonctionnel), puis tapez h dans le moniteur série et validez.

✓ Résultat attendu : la liste des dernières tentatives s'affiche, avec UID, temps écoulé depuis le démarrage, et décision.

Dépannage

  • L'historique reste vide : vérifiez que le code d'enregistrement est bien placé après la détection d'une carte, pas avant.
  • Rien ne s'affiche en tapant « h » : vérifiez que le moniteur série envoie bien un caractère (et pas une ligne entière avec retour chariot qui décale la lecture).

Discussion

En binôme, listez ce qu'il manque à ce système pour être un vrai outil de journalisation en production :

  • Une heure réelle plutôt qu'un temps relatif depuis le démarrage.
  • Un stockage qui survit à une coupure de courant.
  • Un envoi vers un serveur centralisé, consultable à distance.
Livrable : code source commenté, capture d'un historique de plusieurs tentatives (autorisées et refusées), réponses à la discussion.
