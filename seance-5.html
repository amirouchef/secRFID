Lecture/écriture de secteurs Mifare Classic

Fil rouge : vous lisez et modifiez maintenant les données de la carte dont vous avez lu l'UID en séance 4 — c'est cette même carte que vous tenterez de cloner en séance 6.

Cours

1. Structure d'une carte Mifare Classic 1K

La mémoire est organisée en 16 secteurs de 4 blocs de 16 octets chacun (64 blocs au total). Le bloc 0 du secteur 0 contient l'UID et les données constructeur, en lecture seule sur une carte d'origine. Le dernier bloc de chaque secteur (trailer) stocke la clé A, les bits d'accès, et la clé B.

2. Authentification par clé

Chaque secteur est protégé par une authentification sur 48 bits (clé A et/ou clé B). La clé par défaut FFFFFFFFFFFF reste très répandue sur les cartes non reconfigurées — y compris potentiellement la carte et le badge de la mallette.

3. Bits d'accès

Ils définissent, bloc par bloc, les droits de lecture et d'écriture associés à chaque clé. Une mauvaise configuration peut rendre un secteur accessible en écriture sans autorisation légitime.

4. Lire et interpréter un dump réel

Voici un dump complet obtenu sur la carte de la mallette. Apprenez à le lire ligne par ligne avant de lancer votre propre lecture.

Card UID: 09 74 2E A7 Card SAK: 08 PICC type: MIFARE 1KB Secteur 0, bloc 3 (trailer) : 00 00 00 00 00 00 FF 07 80 69 FF FF FF FF FF FF └──── clé A ────┘ └ bits accès┘ └──── clé B ────┘ (illisible, (transport (lisible : clé jamais retourné d'usine = par défaut par le lecteur) inchangés) FFFFFFFFFFFF) Secteur 0, bloc 0 (bloc fabricant, lecture seule) : 09 74 2E A7 F4 08 04 00 01 C3 50 D4 31 5D DD A8 └── UID ───┘ BCC └── données écrites en usine par NXP ──┘ Blocs de données (1, 2 des secteurs 0 à 15) : 00 00 00 00 00 00 00 00 00 00 00 00 00 00 00 00 → tous à zéro : carte vierge, jamais écrite

SAK 0x08 confirme une Mifare Classic 1K. Les bits d'accès FF 07 80 sont la valeur de transport d'usine — signe que la carte n'a jamais été reconfigurée (angle mort de sécurité vu en séance 1). Seule la clé B peut apparaître en clair selon la configuration ; la clé A n'est elle jamais retournée par le protocole, qu'elle soit connue ou non.

Atelier

Objectif : lire le dump complet de la carte, lire un secteur ciblé, puis écrire et relire un bloc de données.

Rappel câblage : le module reste branché comme en séance 4 (VCC sur 3.3V, jamais 5V). Vérifiez le montage avant de rebrancher l'USB.

Étape 1 : lire le dump complet avec DumpInfo

Rechargez Fichier → Exemples → MFRC522 → DumpInfo, présentez la carte, et relevez l'intégralité du dump affiché dans le moniteur série.

✓ Résultat attendu : un dump similaire à celui du cours, avec votre propre UID et vos propres clés/bits d'accès.

Étape 2 : identifier les éléments clés du dump

Sur votre propre dump, repérez et annotez : l'UID (bloc 0), le SAK, les bits d'accès de chaque trailer, et la clé B si elle est visible.

Étape 3 : lire un secteur de données avec la clé par défaut

Téléversez ce sketch pour authentifier puis lire le bloc 4 (premier bloc de données du secteur 1) :

#include <SPI.h>
#include <MFRC522.h>

#define SS_PIN 10
#define RST_PIN 9
MFRC522 rfid(SS_PIN, RST_PIN);
MFRC522::MIFARE_Key key;

void setup() {
  Serial.begin(9600);
  SPI.begin();
  rfid.PCD_Init();
  for (byte i = 0; i < 6; i++) key.keyByte[i] = 0xFF; // clé par défaut
}

void loop() {
  if (!rfid.PICC_IsNewCardPresent() || !rfid.PICC_ReadCardSerial()) return;

  byte block = 4;
  MFRC522::StatusCode status = rfid.PCD_Authenticate(
    MFRC522::PICC_CMD_MF_AUTH_KEY_A, block, &key, &(rfid.uid));
  if (status != MFRC522::STATUS_OK) {
    Serial.print(F("Échec authentification : "));
    Serial.println(rfid.GetStatusCodeName(status));
    return;
  }

  byte buffer[18];
  byte size = sizeof(buffer);
  status = rfid.MIFARE_Read(block, buffer, &size);
  if (status == MFRC522::STATUS_OK) {
    Serial.print(F("Bloc "));
    Serial.print(block);
    Serial.print(F(" : "));
    for (byte i = 0; i < 16; i++) {
      if (buffer[i] < 0x10) Serial.print("0");
      Serial.print(buffer[i], HEX);
      Serial.print(" ");
    }
    Serial.println();
  }
  rfid.PICC_HaltA();
  rfid.PCD_StopCrypto1();
}
✓ Résultat attendu : 16 octets affichés, probablement tous à 00 si la carte n'a jamais été écrite.

Si l'authentification échoue : la clé n'est peut-être pas la clé par défaut (quelqu'un a pu la changer lors d'une séance précédente) — demandez à l'enseignant.

Étape 4 : écrire puis relire un bloc de données

Ajoutez l'écriture juste après l'authentification réussie, avant la lecture :

  byte donnees[16] = {0x52, 0x46, 0x49, 0x44, 0x20, 0x53, 0x45, 0x43,
                       0x55, 0x52, 0x49, 0x54, 0x45, 0x00, 0x00, 0x00};
  status = rfid.MIFARE_Write(block, donnees, 16);
  if (status != MFRC522::STATUS_OK) {
    Serial.print(F("Échec écriture : "));
    Serial.println(rfid.GetStatusCodeName(status));
  }

Téléversez, présentez la carte une fois pour écrire, puis une seconde fois pour relire (ou laissez le code relire juste après l'écriture).

✓ Résultat attendu : le bloc 4 affiche maintenant les octets que vous avez écrits, au lieu de zéros.

Étape 5 : comparer avec le dump réel

Relancez DumpInfo une dernière fois et comparez le nouveau contenu du bloc 4 avec le dump d'origine du cours — c'est la preuve concrète que l'écriture a fonctionné.

Dépannage

  • STATUS_TIMEOUT à l'authentification : la carte a été retirée trop tôt, maintenez-la immobile.
  • Écriture refusée : vérifiez que vous ciblez bien un bloc de données (pas un trailer ni le bloc 0).
  • Mêmes valeurs qu'avant après écriture : le moniteur série affichait peut-être un ancien relevé — relancez une lecture fraîche.
Livrable : dump complet annoté (UID, SAK, bits d'accès), capture avant/après écriture du bloc 4, code source commenté.
