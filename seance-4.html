Arduino + RC522 : câblage, lecture d’UID et liste blanche

Cours

1. Le protocole SPI

Le RC522 communique avec l’Arduino via SPI, un bus série synchrone à 4 fils : MOSI (données maître → esclave), MISO (données esclave → maître), SCK (horloge) et SS/CS (sélection du périphérique, noté NSS ou SDA sur le module).

2. La bibliothèque MFRC522

Elle expose des fonctions haut niveau comme PICC_IsNewCardPresent() et PICC_ReadCardSerial() pour détecter puis lire l’UID d’un tag sans gérer le protocole ISO 14443 bas niveau.

3. Vocabulaire ISO 14443

La norme distingue le PCD (Proximity Coupling Device, le lecteur, ici le RC522) et le PICC (Proximity Integrated Circuit Card, le tag, ici le badge ou la carte). Lors de la détection, le PICC annonce son type par la valeur SAK, que la bibliothèque traduit en nom lisible.

4. Fréquences et familles de tags

125 kHz (EM4100) : identifiant fixe, sans cryptographie. 13,56 MHz (MIFARE, NFC, ISO 14443) : mémoire et mécanismes d’authentification. Le RC522 ne lit que le 13,56 MHz : un badge 125 kHz reste invisible pour lui.

5. UID : identifier n’est pas authentifier

L’UID est lu en clair par n’importe quel lecteur. Il dit « qui je prétends être », pas « je le prouve ». Gardez cette idée en tête jusqu’à la séance 9.

Atelier

Objectif : câbler le RC522, lire l’UID et le type du badge et de la carte, puis construire une liste blanche signalée par deux LED.

Alimentation : 3,3 V uniquement. Le module se branche sur la broche 3.3V de l’Arduino, jamais sur le 5 V, au risque de le détruire. Câblez l’Arduino débranché de l’USB et faites vérifier le montage avant de le brancher.

Étape 2 : installer la bibliothèque

IDE Arduino : Croquis → Inclure une bibliothèque → Gérer les bibliothèques, rechercher MFRC522 (auteur : GithubCommunity), puis Installer.

Étape 3 : valider le module avec DumpInfo

Ouvrez Fichier → Exemples → MFRC522 → DumpInfo, choisissez Arduino Uno et le bon port, téléversez, puis ouvrez le moniteur série. Vous devez lire Firmware Version: 0x91 ou 0x92. Avec 0x00 ou 0xFF, le câblage est en cause.

Étape 4 : lire l’UID et le type de tag

Téléversez ce sketch, moniteur série à 9600 bauds, puis présentez le badge, puis la carte (à 2-3 cm du module). Relevez les deux UID et les deux types.

#include <SPI.h>
#include <MFRC522.h>

#define SS_PIN 10    // broche NSS du module
#define RST_PIN 9

MFRC522 rfid(SS_PIN, RST_PIN);

void setup() {
  Serial.begin(9600);
  SPI.begin();            // démarre le bus SPI
  rfid.PCD_Init();        // initialise le lecteur (PCD)
  Serial.println(F("Presentez un badge ou une carte..."));
}

void loop() {
  // sortir si aucun tag n'est présenté ou si la lecture échoue
  if (!rfid.PICC_IsNewCardPresent() || !rfid.PICC_ReadCardSerial()) return;

  // type du tag, déduit de la valeur SAK
  MFRC522::PICC_Type type = rfid.PICC_GetType(rfid.uid.sak);
  Serial.print(F("Type : "));
  Serial.println(rfid.PICC_GetTypeName(type));

  // affichage de l'UID en hexadécimal, octet par octet
  Serial.print(F("UID  : "));
  for (byte i = 0; i < rfid.uid.size; i++) {
    if (rfid.uid.uidByte[i] < 0x10) Serial.print("0");
    Serial.print(rfid.uid.uidByte[i], HEX);
    if (i < rfid.uid.size - 1) Serial.print(":");
  }
  Serial.println();

  rfid.PICC_HaltA();       // met le tag en veille
  rfid.PCD_StopCrypto1();  // coupe l'éventuelle session chiffrée
}

Étape 5 : liste blanche avec LED

Rappel : fonctionnement de la platine d’essai

  • La platine compte 30 colonnes numérotées. Chaque colonne comporte deux groupes de 5 trous : a à e et f à j.
  • Les 5 trous d’un même groupe sont reliés entre eux. La rainure centrale isole a-e de f-j, et deux colonnes différentes ne sont jamais reliées.
  • Les deux rails latéraux (+ rouge, − bleu) sont reliés sur toute leur longueur. Ils servent ici de ligne de masse (GND). Sur certains modèles le rail est coupé au milieu : vérifiez-le avant de vous y fier.
  • Le courant ne circule que si les composants forment une boucle fermée : sortie de l’Arduino, résistance, LED, retour vers GND.

Composants : la résistance de 220 Ω (bandes rouge, rouge, marron) n’a pas de sens de branchement et limite le courant à environ 15 mA. La LED, elle, est polarisée : la patte longue est l’anode (+, côté résistance), la patte courte (côté plat du boîtier) est la cathode (−, côté GND). Sans résistance, la LED et la broche de l’Arduino risquent d’être détruites.

Chemin du courant pour la LED verte : D5, colonne 5, résistance, colonne 8, anode, cathode, colonne 9, rail −, GND. Le module RC522 reste câblé comme à l’étape 1 ; ne reliez pas sa broche 3.3V aux rails.

Vérification avant la liste blanche : USB débranché, contrôlez le sens des LED et la position des résistances. Puis testez chaque LED seule avec Fichier → Exemples → 01.Basics → Blink en remplaçant LED_BUILTIN par 5, puis par 6. Si une LED ne s’allume pas, retournez-la.

Remplacez l’UID d’exemple par celui de votre badge relevé à l’étape 4, puis testez avec le badge et avec la carte. Commentez chaque bloc dans vos propres mots : c’est une partie du livrable.

#include <SPI.h>
#include <MFRC522.h>

#define SS_PIN 10
#define RST_PIN 9
const byte LED_VERTE = 5;
const byte LED_ROUGE = 6;

MFRC522 rfid(SS_PIN, RST_PIN);

// UID autorisé : A REMPLACER par celui de votre badge
byte uidAutorise[4] = {0xA3, 0x5F, 0x12, 0x9C};

void setup() {
  Serial.begin(9600);
  SPI.begin();
  rfid.PCD_Init();
  pinMode(LED_VERTE, OUTPUT);
  pinMode(LED_ROUGE, OUTPUT);
}

void loop() {
  if (!rfid.PICC_IsNewCardPresent() || !rfid.PICC_ReadCardSerial()) return;

  // autorisé si la taille et tous les octets de l'UID correspondent
  bool autorise = (rfid.uid.size == sizeof(uidAutorise)) &&
                  (memcmp(rfid.uid.uidByte, uidAutorise, sizeof(uidAutorise)) == 0);

  Serial.println(autorise ? F("ACCES AUTORISE") : F("ACCES REFUSE"));
  digitalWrite(autorise ? LED_VERTE : LED_ROUGE, HIGH);
  delay(2000);
  digitalWrite(LED_VERTE, LOW);
  digitalWrite(LED_ROUGE, LOW);

  rfid.PICC_HaltA();
  rfid.PCD_StopCrypto1();
}

Dépannage

  • Rien ne s’affiche : vérifiez NSS→D10 et RST→D9, puis MOSI et MISO, souvent inversés.
  • Caractères illisibles : le moniteur série n’est pas réglé sur 9600 bauds.
  • Lecture intermittente : broches du module non soudées ou mal soudées.
  • LED muette : sens de la LED inversé (patte longue côté résistance).
Cadre d’usage. Ne lisez que les badges et cartes fournis pour le TP ou vos propres cartes, avec le consentement de leur propriétaire. Lire le badge d’un tiers sans son accord est interdit. Le cadre légal est détaillé en séance 6.
